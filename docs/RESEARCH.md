# フェーズ1 リサーチ：ソシャゲ風ガチャの解剖

> 目的：「ソシャゲ風ガチャ」を *完全に再現* するために、何が「ソシャゲ風」を構成しているのかを
> 演出 / 確率設計 / 経済 / UX / 音響 / 法規制 の6軸で分解する。
> 本書はフェーズ2（計画書）の入力であり、実装中の判断基準（= 仕様の根拠）として参照する。

---

## 0. 要約：ソシャゲガチャの本質は「確率」ではなく「情報の出し方」

抽選そのものは `Math.random()` 1行で終わる。プレイヤーが金と時間を払っているのは
**「結果を知るまでの 3〜12 秒間の情報開示プロセス」** である。

```
[抽選は一瞬で終わっている] → [結果を隠す] → [少しずつヒントを漏らす] → [裏切る/報いる] → [開示]
                                    ↑ここが商品
```

この「少しずつ漏らす」設計が **演出（えんしゅつ）** であり、ソシャゲガチャの中核である。
本プロジェクトは演出・雰囲気・効果音・気持ちよさを最優先事項とするため、
リサーチも演出工学に最大の分量を割く。

---

## 1. 演出（Production / Staging）

### 1.1 演出の基本構造 — 「期待度の階段」

ほぼ全ての大手タイトルが共通して採用する構造：

| 段階 | 名称 | 役割 | 代表的な時間 |
|---|---|---|---|
| 0 | 予兆 / Anticipation | UIが暗転、BGMがダック、環境音が消える。「これから何か起きる」 | 0.3–0.8s |
| 1 | 投入 / Insert | 石・チケット・コインを投入。物理的な「対価を払った」実感 | 0.4–0.8s |
| 2 | 詠唱 / Charge | エネルギー収束、光の渦、ライザー音。緊張を積む | 1.0–2.0s |
| 3 | **色の確定 / Aura** | **ここで期待度が開示される（白→青→銀→金→虹）** | 0.6–1.2s |
| 4 | 昇格 / Upgrade | 一度決まった色がさらに上がる（最大の快感ポイント） | 0.4–0.9s |
| 5 | 解放 / Burst | 光柱・画面白飛び・画面揺れ・オーケストラヒット | 0.3–0.6s |
| 6 | カットイン / Cut-in | ★5確定時のみ。キャラ大写し + 名前スラム | 1.0–1.8s |
| 7 | 顕現 / Reveal | カードが出現・フリップ・枠が組み上がる・星が1つずつ点灯 | 0.8–1.6s |
| 8 | 余韻 / Afterglow | 粒子が漂う、NEWバッジ、パッドコードの残響 | 0.6–1.5s |

**重要**：この階段は「一本道」ではない。**各段で分岐する**から面白い。

### 1.2 色による期待度コード（業界共通言語）

調査したタイトル（FGO / ウマ娘 / ドッカンバトル / グラブル / 学園アイドルマスター / 遊戯王マスターデュエル / 幻想水滸伝SP / リゼロス / AFKジャーニー 他）で、
**色 → レアリティ期待度のマッピングはほぼ統一されている**：

| 色 | 一般的な意味 | 備考 |
|---|---|---|
| 白 / 無色 | 最低保証のみ | 「ハズレ確定」ではなく「昇格の余地あり」として使う |
| 青 | ★2〜 | |
| 銀 | ★3以上確定 | FGO：銀回転＝星3以上 |
| 金 | ★4以上確定 | FGO：金回転＝星4以上確定 / 遊戯王MD：カード裏が金＝SR確定 |
| **虹** | **★5確定** | ほぼ全タイトルで「虹＝最高レア確定」 |
| 特殊（暗転・特殊色） | 特定カテゴリ確定 | FGO：画面暗転＝ビーストクラス確定 |

> 設計指針：**虹を安売りしない**。虹は0.6%の事象であり、虹を見た瞬間に鳥肌が立つよう、
> 他の色との演出差を「量」ではなく「質」で断絶させる（後述 §1.5）。

### 1.3 昇格演出（Upgrade / Promotion）— 最大の発明

> 「最初に表示されたパックで光っていなかったものでも、昇格して金や虹になることがある」
> 「通常色のカードが『バチバチ』と音を鳴らして金色に変化する＝星4以上確定」
> 「柱の色が変わったらランクが上がる昇格演出」

**なぜこれが効くのか（心理学的機序）**

1. **期待値のリセット**：一度「白（ハズレ）」と確定させ、プレイヤーの期待値を床まで落とす。
2. **予測誤差報酬**：ドーパミンは「報酬そのもの」ではなく「予測より良かった差分（Reward Prediction Error）」に反応する。
   床から虹への昇格は、最初から虹だった場合より **報酬予測誤差が最大化** される。
3. **全ての回に意味が生まれる**：昇格がある限り、白オーラでも最後まで見る理由がある。
   → 演出スキップ率が下がり、体験時間が延びる。

**実装上の必須要件**

- 昇格は **抽選結果から逆算して演出を組む**（演出が結果を決めるのではない）。
- 昇格の「段数」自体を抽選する：0段（ストレート）/1段/2段/3段（大逆転）。
- 段数が多いほど稀にする → 「3段昇格」自体がレアな体験として語られる。
- 各段の SFX は **必ず音色を変える**（バチッ → ビキィッ → 轟音＋合唱）。同じ音の繰り返しは緊張を生まない。
- **昇格の「タメ」**：色が変わる前に 120–250ms の無音（またはサブベースのみ）を挿す。無音は最強の効果音。

### 1.4 10連ガチャ特有の演出文法

| 要素 | 内容 |
|---|---|
| 一斉射出 | 10個のオーブが扇状に打ち上がる。まとめて「払った感」を出す |
| カード配り | 10枚が机/空間に配られる。1枚ずつ 40–70ms スタガー、着地音はピッチ±2半音のランダム化 |
| **裏面ヒント** | カード裏の色でレアを事前告知。虹裏＝★5確定、金裏＝★4確定 |
| 裏面昇格 | 配り終えた後に裏面が昇格する（バチバチ） |
| めくり | 1枚ずつタップ / 一括めくり / スキップ の3経路を必ず用意 |
| **最良札は最後** | 最高レアのカードを必ず最後にめくらせる（順序を並べ替える）。クライマックス設計 |
| 単発演出へ昇華 | 最後の1枚が★5なら、そこで単発フル演出（カットイン込み）に移行 |
| 確定枠 | 10連内に★3以上 or ★4以上を1枚保証（業界標準） |

### 1.5 「虹を特別にする」ための演出差の作り方

量（パーティクル数・時間）を増やすだけでは特別にならない。**質的断絶**を入れる：

- **音楽の停止**：BGMを完全に止める（フェードではなくカット）。虹のときだけ。
- **無音 → 合唱**：0.3秒の完全無音のあと、合唱（Choir）が入る。
- **時間の歪み**：ヒットストップ（60–120ms のフリーズ）＋スローモーション。
- **画面の物理的破壊表現**：ガラス割れ、色収差（chromatic aberration）、走査線の乱れ。
- **カメラワークの変化**：他レアは正面固定、虹だけカメラが回り込む / ズームアウト→スラムズームイン。
- **専用ファンファーレ**：★5にだけ固有の4〜6音のファンファーレ。

### 1.6 「気持ちよさ（Game Feel / Juice）」の技術リスト

> 出典整理：Disney 12原則、Squirrel Eiserloh のトラウマ型シェイク、Jan Willem Nijman の "Art of Screenshake"

| 技法 | 適用箇所 | パラメータ指針 |
|---|---|---|
| **Anticipation（予備動作）** | ボタン押下時に一瞬縮む → 離すと弾む | 縮み 60ms / 戻り 180ms |
| **Squash & Stretch** | カード出現・着地 | scaleY 1.12 → 0.92 → 1.0 |
| **Overshoot / Back easing** | UIのスライドイン、カードフリップ | overshoot 1.7 |
| **Hit-stop（ヒットストップ）** | 大インパクトの瞬間に全アニメを停止 | ★3:0ms ★4:45ms ★5:110ms |
| **Screen shake（トラウマ型）** | インパクト | trauma を加算、shake = trauma²、毎フレーム trauma *= 0.92。回転も混ぜる |
| **Flash / 白飛び** | 解放の瞬間 | 1フレーム完全白 → 120ms で減衰 |
| **Chromatic aberration** | 虹演出、昇格 | R/Bチャンネルを ±3〜8px オフセット |
| **Radial blur / ズームブラー** | カットイン | 中心からの放射状ストリーク |
| **Particle burst** | 全インパクト | 火花・光粒・破片・リボン・花弁の5種を使い分け |
| **Trail / 残像** | 飛翔物 | 前フレームを alpha 0.85 で残す |
| **Time dilation** | ★5開示直前 | timeScale 0.25 を 200ms |
| **Pitch variation** | 全SFX | ±2半音のランダム化（同じ音の連打を避ける） |
| **Layered SFX** | インパクト | 「トランジェント＋ボディ＋テイル」の3層構成 |
| **Haptics** | タップ・インパクト | navigator.vibrate のパターン化 |
| **Input responsiveness** | 全操作 | 音は押下から 50ms 以内。視覚は 1フレーム以内 |

> 核心原則：**「responsiveness（即応性）＋ readability（可読性）」が土台で、juice はその上のフィードバック層**。
> juice だけ盛っても、入力が重い / 何が起きたか読めない、なら気持ちよくならない。

### 1.7 スキップ設計（これを怠ると体験が壊れる）

- 1回目は必ずフル演出（初見の感動を奪わない）。
- 2回目以降は「早送り」ボタンを常時表示。
- 連続スキップを数回すると **「以降スキップしますか？」** を提案（調査事例あり）。
- 設定に「演出スキップ：なし / 短縮 / 全スキップ」「★4以上のみフル演出」を用意。
- **スキップしても結果の快感は削らない**：スキップ時も結果画面のファンファーレと NEW バッジは残す。

## 2. 確率設計（Probability / Pity）

### 2.1 基本レート（業界の代表値）

| ゲーム | 最高レア | 次点 | 天井 | ソフト天井 |
|---|---|---|---|---|
| Genshin Impact（キャラ） | 0.6% | 5.1% | 90 | 74〜75から急増 |
| Genshin Impact（武器） | 0.7% | 6.0% | 80 | 65〜 |
| Honkai: Star Rail | 0.6% | 5.1% | 90 | 74〜 |
| 幻想水滸伝SP 等 | — | — | 200連 | — |

### 2.2 ソフト天井（Soft Pity）

- ハード天井（例：90連目で確定）だけだと、確率分布が「ほぼ一様 + 90にスパイク」となり体感が悪い。
- ソフト天井は **74連目あたりから 1連ごとに約 +6% ずつ最高レア率を加算** する。
  結果、実際の最高レア取得は 75〜80連に集中する。
- 効果：
  - 「そろそろ来る」という**予測可能な希望**が生まれる。
  - 90連まで引かされる人がほぼいなくなる（体感ストレスの緩和）。
  - **総合実効確率が約 1.6% 程度**に上がる（0.6%の公称より体感が良い）。

### 2.3 50/50（ピックアップ突破抽選）

1. 最高レアを引く。
2. 50%でピックアップキャラ、50%で恒常キャラ（＝「すり抜け」）。
3. すり抜けた場合、**次の最高レアはピックアップ確定**。
4. → 最悪でも 180連でピックアップが確定する（＝実質的な二重天井）。

> 重要な演出上の知見：**虹演出はピックアップ確定演出ではない**。
> すり抜けの場合も虹は出る。だからこそ「虹 → すり抜け」の落差が語られる。
> この落差はゲーム体験として重要なので、再現する（ただし救済を明示する）。

### 2.4 天井カウンタの引き継ぎ

- 同種バナー間では天井カウンタを持ち越す（キャラ↔キャラ）。
- 異種バナー間では持ち越さない（キャラ↔武器）。
- すり抜けフラグ（guaranteed）も同種バナー間で持ち越す。

### 2.5 10連保証

- 10連の中に★3以上を1枚以上保証（実装：10連ごとの★4ピティ）。
- 「10パック買ってURが出なければ、次の同パックでUR1枚以上確定」型（マスターデュエル系）も存在。

### 2.6 ステップアップガチャ

- 1回目：通常 / 2回目：割引 / 3回目：★4確定 / 5回目：**★5確定** のように段階報酬。
- 終了後はステップ1に戻る（ループ型）か、終了（一回限り型）。
- 強い購買動機を作るが、本作では「無償通貨のみ」で完結させる（§6 倫理方針）。

### 2.7 抽選アルゴリズムの実装論

```
1. レアリティを決める（ピティ補正後の重みテーブルから累積和 + 二分探索）
2. そのレアリティ内で「ピックアップ枠 / 恒常枠」を決める（50/50 など）
3. 枠の中から個体を決める（均等 or 重み付き）
4. 重複判定 → 欠片(shard)へ変換
5. ピティカウンタ更新
6. 「演出プラン」を結果から逆算して生成  ← ここが演出設計との接続点
```

- **RNG の質**：`Math.random()` は実装依存。再現性・検証性のため
  **mulberry32 / xorshift128+ などのシード可能 PRNG** を自前で持つ（デバッグ・統計テストに必須）。
- **確率操作は行わない**（§6）。ただし「ピティ」は事前に開示された仕様なので操作ではない。

## 3. 経済設計（Economy）

| 要素 | 内容 |
|---|---|
| 有償/無償通貨 | 本作は**無償通貨のみ**（星晶石）。課金導線は作らない |
| 収入源 | 初回付与 / デイリーボーナス / 実績 / ログイン連続 / 重複変換 |
| 単価 | 単発 = 150、10連 = 1500（割引なし＝連数を稼がせない誠実設計） |
| 重複 | 欠片（shard）に変換。レアほど大量。→ 交換所で任意の★4/★5と交換 |
| 交換所 | 「祈刻（Fate Chip）」を1連ごとに1枚付与、**200枚でピックアップ★5と確定交換**（＝真の天井） |
| 無料枠 | 1日1回の無料単発（リテンション設計の基本） |
| 実績 | 「初めての★5」「3段昇格を見た」「天井到達」など、演出体験自体を実績化 |

## 4. UX / 情報設計

### 4.1 必須の画面

- ホーム（所持通貨、デイリー、お知らせ）
- バナー選択（複数バナー、期間、ピックアップ紹介）
- **提供割合（レート）表示** ← 法的・倫理的に必須（§6）
- 天井カウンタ（あと何連で確定か、すり抜けフラグの有無）を**常時可視化**
- 結果一覧（NEWバッジ、レア度ソート、獲得欠片）
- コレクション（図鑑、取得率、重複数）
- 交換所
- **履歴 / 統計**（引いた回数、レア別実績、実効確率、最長未排出）
- 設定（音量3系統、演出品質、スキップ、モーション削減、色覚配慮、データ削除）

### 4.2 見せるべき数字（信頼の設計）

| 数字 | 理由 |
|---|---|
| 各レアリティの提供割合 | 業界自主規制の基本要件 |
| ピックアップ個別の提供割合 | 「ピックアップ0.3%」など個別開示 |
| 天井までの残り回数 | 不安の解消 |
| すり抜け済みフラグ | 次が確定であることの明示 |
| 現在のソフト天井補正後の実確率 | **通常のソシャゲは出さない情報**。誠実さの差別化として出す |
| 実効確率（自分の履歴での実績値） | 「確率操作されている」疑念への回答 |

### 4.3 アクセシビリティ（演出を作る以上、必須）

- `prefers-reduced-motion` を尊重（自動で演出短縮モードへ）。
- **光過敏性発作（PSE）対策**：毎秒3回を超えるフラッシュを避ける、赤の強いフラッシュを避ける、
  画面面積の大きい高輝度点滅を連続させない。初回起動時に警告を出す。
- 色だけに依存しない：レア度は色＋形（★の数）＋テキストで冗長表現。
- 音量は BGM / SFX / ボイス（本作ではUI）で独立。ミュート記憶。
- キーボード操作（Enter/Space で召喚、Esc で戻る、S でスキップ）。
- 全インタラクティブ要素に aria-label と focus-visible。

## 5. 音響設計（Sound Design）

### 5.1 ソシャゲガチャ音の構成要素

| 音 | 役割 | 合成方針（プロシージャル） |
|---|---|---|
| UIタップ | 即応性の担保 | 短いFMブリップ（5–15ms attack） |
| 石投入 | 対価の実感 | 非整数倍音FM（金属感）＋ノイズトランジェント |
| ライザー（Riser） | 緊張の蓄積 | ノコギリ波＋ノイズのフィルタスイープ＋ピッチランプ。Shepard風の多層化で無限上昇感 |
| チャージ | 収束の表現 | デチューンsaw + カットオフ上昇 + トレモロ |
| バチバチ（昇格） | 驚きの合図 | 帯域通過ノイズのグレイン群＋リングモジュレーション |
| インパクト | 解放 | **3層**：①トランジェント（ノイズ） ②ボディ（サブ 80→30Hz のピッチドロップ） ③テイル（リバーブ） |
| 和太鼓 | 和風の重厚感 | サイン波の高速ピッチエンベロープ＋ノイズボディ |
| 合唱（Choir） | 荘厳さ | 加算合成のサイン/sawスタック＋フォルマント帯域＋長いアタック＋大リバーブ |
| オケヒット | 決定感 | ノイズ＋sawクラスタ＋サブ、ゲート処理 |
| ガラス破砕 | 破壊表現 | 多数の短いノイズグレイン（ランダムHPF/ピッチ） |
| 星点灯チャイム | 報酬感 | FMベルの上昇アルペジオ（★の数だけ） |
| ファンファーレ | ★5専用 | Saw スタック＋ローパスエンベロープの4〜6音 |
| ウーッシュ | 移動感 | ノイズのバンドパススイープ＋パンニング |

### 5.2 技術方針（Web Audio API、サンプル素材ゼロ）

- **マスターチェーン**：`buses → Compressor(limiter) → masterGain → destination`
- **バス**：`bgm` / `sfx` / `ui` を独立ゲインで（設定と直結）
- **リバーブ**：`ConvolverNode` に **プログラム生成した IR**（ノイズ×指数減衰、ステレオ、プリディレイ付き）を投入。
  ホール（3.5s）とルーム（0.4s）の2種。
- **サブ帯域**：40〜60Hz のサイン。スマホスピーカーでは鳴らないが、体感の「厚み」に寄与しヘッドホンでは決定的。
- **ダッキング**：演出中は BGM ゲインを 0.25 へ、虹演出では完全に 0（カット）へ。
- **ポリフォニー管理**：同時発音数の上限と、同名SFXの最小間隔（例 30ms）を設ける。
- **AudioContext の解禁**：ブラウザ制約により、必ず**最初のユーザー操作で `resume()`**。
- **スケジューリング**：`currentTime + lookahead` で正確に予約。`setTimeout` に頼らない。
- **音楽理論**：荘厳さは「完全5度の積み重ね」「Lydian/Aeolian」「長2度のクラスタ」で作る。
  ★5ファンファーレは **I → V → vi → IV**（王道進行）ではなく **i → VI → III → VII**（エピック進行）を使う。

### 5.3 BGM（アダプティブ）

- レイヤー構成：`pad`（持続和音） / `arp`（分散和音） / `pulse`（低音の鼓動） / `tension`（不協和なストリングス風）。
- 状態遷移でレイヤーを出し入れ：
  - ホーム：pad + arp（穏やか）
  - バナー画面：pad + arp + pulse
  - チャージ中：tension をフェードイン、テンポ感を上げる
  - 虹演出：全カット → 静寂 → 合唱
  - 結果画面：勝利感のあるコード進行

## 6. 法規制・倫理（これを外すと「再現」ではなく「模倣の失敗」になる）

### 6.1 日本の規制・自主規制

- **2012年5月18日**：消費者庁がコンプガチャを景品表示法の「カード合わせ」に該当と判断。
  **2012年7月1日から規制開始**。→ **コンプガチャは実装しない**。
- **JOGA ガイドライン（2012年8月15日発表 / 9月1日施行、以降改訂）**：
  - 有料ガチャで取得できる全アイテムとその**提供割合の表示**を原則とする。
  - レアアイテム取得までの**推定金額の上限は、1回あたり課金額の100倍以内**。
    超える場合はガチャページに推定金額または倍率を表示。
  - **推定金額の上限は 50,000 円以内**とする選択肢。超える場合は推定金額を表示。
  - ガチャレアアイテムの提供割合の**上限と下限**を表示。
- **CESA ガイドライン（2016年4月27日施行）**：同様に提供割合表示を原則化。
- 提供割合表示は**法律上の一律義務ではなく業界自主規制**だが、事実上の標準。

### 6.2 本プロジェクトの倫理方針（明示）

1. **実課金・課金導線は一切実装しない。** 通貨はすべてゲーム内無償。
2. **確率操作は行わない。** ピティ（天井/ソフト天井/50-50）は全て**事前開示された仕様**として明記。
3. **提供割合を全レアリティ・全ピックアップについて開示**（JOGA/CESA 準拠の形で）。
4. **天井までの残回数・すり抜けフラグを常時可視化**。
5. **コンプガチャ型（複数アイテムの収集で別報酬）は実装しない。**
6. **ダークパターンを使わない**：
   - 偽のカウントダウン、偽の「他の人が引いています」、離脱を妨げるモーダルは作らない。
   - 「あと少しで天井」を煽る通知は出さない。
7. **PSE（光過敏性発作）配慮**を実装し、初回に注意喚起を出す。
8. これは**シミュレータ**であり、実在のギャンブルではないことを明記する。
